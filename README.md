# FF14副本復盤記錄

**網頁版：<https://crystal1207.github.io/FF14_ultimate_review/>**

把記錄的戰鬥紀錄（log）和你的 YouTube 第一視角影片對齊。點左邊的場次、時間軸上的 Boss 招式、技能或死亡，影片就會跳到那一刻；還會標出 GCD 空轉，方便打完副本後檢討。所有職業都適用，不需要 FFLogs 帳號。

純前端網頁：log 只在你的瀏覽器裡解析，**不會上傳到任何地方**。

作者：紅月@迦樓羅

## 需求

- 電腦版 Chrome 或 Edge（建議；「選擇資料夾」和「讀取畫面時鐘自動校正」只有這兩個支援）。Firefox 可以用，但要每次選檔案、手動校正
- 打本時有開 ACT（FFXIV 插件）或 IINACT，會在電腦上留下 `Network_*.log`
- 錄影畫面裡要有電腦時鐘（例如 OBS 加一個顯示本機時間的文字來源），用來對齊時間
- YouTube 影片要設成「公開」或「不公開」。「私人」影片無法嵌入播放

## 使用方式

1. **選 log**：按「選擇資料夾…」選 ACT 的 log 資料夾（通常是 `%APPDATA%\Advanced Combat Tracker\FFXIVLogs`），之後每次打開都會自動列出每天的 log。也可以按「選擇檔案…」直接選一個檔案
2. 貼上 YouTube 影片網址，按「載入」。1 GB 左右的 log 大約 10 秒
3. **選場次**：還沒校正時，左上可以選日期（凌晨 6 點前算前一天）和副本。點一把這部影片裡打的場次
4. **時間校正**（每部影片一次，會記住）：打開「時間校正」，按「讀取畫面時鐘自動校正」
5. 校正後，左邊只會列出影片時段內的場次。點任一場，影片就會跳到那一場開打前；點時間軸上的 Boss 招式、技能或死亡標記，影片會跳到該時間點前幾秒（「提前」可以調整）
6. **我的職業**：預設是 log 記錄者（ACT 的主角）在這段時間玩的職業；不對的話選影片裡你玩的職業，每部影片會分別記住。選單只列出目前這一把隊伍裡有的職業

### 時間校正

log 的時間和畫面上的時鐘是同一個電腦時鐘，校正就是找出「影片第幾秒＝時鐘幾點幾分」。

- **讀取畫面時鐘自動校正（最準）**
  1. 第一次使用時，畫面會放大，請拖曳框住時鐘的「數字」（之後會記住；位置變了再按「重新框選時鐘」）
  2. 瀏覽器會詢問要分享哪個畫面，選「這個分頁」（瀏覽器規定每次都要同意，網頁無法略過）
  3. 程式會先用 OCR 讀出大概的時間（讀不出來會請你輸入畫面上的時間），再自動控制影片找出時鐘跳分鐘的那一格，並找下一分鐘的跳分互相驗證，大約 1～2 分鐘
  4. 兩次結果一致才會套用（誤差通常在 0.1～0.2 秒內）；不一致會顯示原因，原本的校正不變
  - 建議先在播放器的齒輪把畫質調到 1080p，畫質太低（360p）可能失敗
  - 過程中會暫時換成沒有按鈕的播放器（YouTube 的按鈕可能蓋住時鐘），結束後自動換回來
  - 畫面時鐘只有時間沒有日期：程式會選「影片時段內打的場次最多」的那一天。配錯天時，打開「時間校正」用最上面的「日期」選單改成正確的那天
- **方法一**：暫停在時鐘剛跳到新分鐘的那一格（可以用「−1格／+1格」和 0.25× 慢放找），輸入畫面上的時間（例如 `0:04`），按「目前畫面＝這個時間」
- **方法二**：暫停在選取的這一把剛開打的那一格，按「目前畫面＝這一把開打」
- **手動微調**：時間軸上方的「時間軸偏移」
  - 技能標記比影片畫面早就按「＋」，比畫面晚就按「−」（±0.1 秒、±1 秒），也可以直接輸入秒數
  - 快捷鍵：`[` / `]` 每次 0.1 秒，`Shift+[` / `Shift+]` 每次 1 秒
  - 偏移量以校正結果為基準，按「還原」回到校正結果

校正後，上方「本機」時間會跟畫面上的時鐘一致；時鐘跳分鐘時，這裡應該剛好是 `:00`。

ACT 還在記錄時（當天邊打邊看），按「重新整理」會重新讀取最新的 log。

### 時間軸

| 列 | 內容 |
|---|---|
| 時間 | 從這一把開打起算；開打前（倒數時的起手）是斜線區、負秒數。點這一列會直接跳到該秒 |
| 目標 | 依隊伍正在打的主要敵人推測的區段（log 沒有官方的 P1、P2 資訊） |
| Boss | 敵人的招式，色條長度就是讀條時間；虛線框代表讀條被中斷 |
| GCD | 你的 GCD 技能，有讀條的會畫出讀條條；紅框代表讀條被取消或打斷；近戰身位技右下角有 ✔／✘（見下方「身位」） |
| 間隔 | 每兩個 GCD 之間的間隔（見下方「GCD 空轉」） |
| oGCD | 你的能力技，以及你的寵物（小仙女、召喚獸等）技能（綠框） |
| 死亡 | 全隊死亡，滑鼠移上去可以看是被哪一招打死；你自己的死亡會標成「我」 |

GCD／oGCD 的分類和技能圖示來自 [XIVAPI](https://v2.xivapi.com/) 的遊戲資料，所以任何職業都適用。技能名稱直接用 log 裡的名稱，也就是你遊戲客戶端的語言。

### GCD 空轉

「間隔」列把每兩個 GCD 之間畫成一段，滑鼠移上去可以看實際間隔和最快能按的間隔：

- **淡藍色**：正常
- **紅色＋秒數**：空轉，比最快能按的時間慢了 0.3 秒以上（例如 `+1.2` ＝ 晚了 1.2 秒才按下一個 GCD）
- **灰色斜線**：停手超過 8 秒，通常是轉場或 Boss 無法攻擊，不算空轉
- **暗色**：你死亡中

時間軸上方會顯示這一把的摘要，例如「GCD 約 2.49 秒（推算）· 空轉 3 次、合計 5.6 秒」。

最快能按的間隔＝這個技能的 GCD 冷卻 × 你的技速／詠速，有讀條的技能則至少是讀條時間＋0.1 秒（被即刻詠唱、連續詠唱縮短的讀條，用 log 裡的實際讀條時間）。技能冷卻來自 XIVAPI；技速／詠速無法從 log 直接得知，用這一把裡連續施放 GCD 的常見間隔推算。

推算不準的話，可以在時間軸上方的「GCD ＿ 秒」填你這個職業的實際 GCD（例如角色面板上的 2.42），每個職業分別記住；清空就回到自動推算。舞步（1 秒）、標準／技巧舞步（1.5 秒）、忍者結印（0.5 秒）另外處理。

躲機制、被擊退、走位造成的空轉也會被標出來，要不要算失誤請自己對照影片判斷。

### 身位

近戰的身位技（武僧、龍騎、忍者、武士、釤鐮客、蝰蛇劍士）在 GCD 圖示右下角會標：

- **綠色 ✔**：有打到身位
- **紅色 ✘**：沒打到
- **半透明**：遊戲紀錄判斷不出來，改用你當時站的位置推測

滑鼠移上去會寫需要的位置、有沒有開真北、當時站在 Boss 的哪一面。時間軸上方的摘要會加上「身位 32/40（80%）」。

判定方式：遊戲每一下傷害都會記一個「加成百分比」（FFLogs 叫 bonusPercent），打到身位時這個數字比較高。確切的數字會隨連擊、buff、版本改變，所以程式會用整份 log 的資料，看「這個數字出現時，玩家是不是真的站在正確的位置（或開著真北）」，學出哪些數字代表打到。站位用 log 裡玩家和 Boss 的座標、Boss 的面向計算。

- 沒有身位要求的 Boss，遊戲一律算打到，所以會顯示 ✔
- 連擊斷掉時，加成也會變低，有可能被標成 ✘
- 判定表是用 7.x 的 log 統計的；改版調整威力後，程式會用你這份 log 重新學，但 log 太短、資料太少時可能比較不準

### 死法統計（趣味）

按時間軸圖例最右邊的「死法統計（趣味）」，會在筆記下方展開「死法頒獎典禮」，統計左邊列表裡所有場次的死法。只頒準確度高的獎項：

| 獎項 | 條件 |
|---|---|
| ⚰️ 地板常客 | 死最多次 |
| 🚩 開路先鋒 | 最常是該把第一個倒下的人 |
| ⚡ 電網之友 | 走出（或被擊退出）場地邊界撞到電網：死亡沒有兇手、最後一下不是持續傷害（DoT），而且死的位置在場地邊緣（以 (100, 100) 為中心、17 碼以外） |
| ⚖️ 把你加入減傷軸 | 不是坦克，卻被死刑打死。死刑是從這份 log 自動找出來的：Boss 有讀條、每次只打 1～2 人、而且被打的人 75% 以上是坦克的招式（至少出現 4 次）。坦克倒了以後死刑轉到別人身上也算 |
| 🔪 一刀入魂 | 滿血（90% 以上）被一招直接打死 |
| 🎯 易傷收藏家 | 身上帶著受傷加重（易傷）還硬吃，被打死 |
| 💀 死神的約定 | 死亡宣告時間到 |
| 🌊 一招團滅 | 同一招在幾秒內帶走 6 人以上 |

每一筆後面會寫被哪個 Boss 的哪一招殺死（最後一下是持續傷害時寫「被持續傷害（DoT）殺死」）；不屬於這些獎項的死亡列在「其他死法」。點任一筆會跳到影片死亡前幾秒。

### 每一把的判定方式

- **開打**：隊伍第一次打到敵人（或被敵人打到）
- **結束**：遊戲的勝利或滅團（畫面淡出）訊號；沒有訊號時，30 秒沒有戰鬥就算結束
- 少於 15 秒的戰鬥不列出
- 滅團時顯示的是最後在打的 Boss 和剩餘血量

### 快捷鍵

| 按鍵 | 功能 |
|---|---|
| 空白鍵 | 播放／暫停 |
| ← / → | 上一個／下一個事件 |
| J / L | 倒退／前進 5 秒 |
| , / . | 倒退／前進一格 |
| D | 下一次死亡 |
| P / N | 上一把／下一把 |
| [ / ] | 時間軸偏移 −0.1／+0.1 秒（加 Shift 為 1 秒） |

勾選「自動切換」時，播放跨到下一把會自動切換時間軸。每一把都可以寫筆記，有筆記的把數會在左邊標示。

## 試用

頁面上的「用範例 log 試試看」會載入 `public/sample/Network_sample.log`（程式產生的假資料，沒有對應的影片）。要重新產生：

```
npm run sample
```

## 資料存放

全部存在你的瀏覽器裡（localStorage／IndexedDB），清除網站資料就會消失：

- 筆記、每部影片的校正值
- 技能資料快取
- 選過的 log 資料夾（只記得位置，讀取前瀏覽器會確認權限）

## 開發

不需要安裝任何套件。本機預覽：

```
npm start
```

（或雙擊 `start.bat`）然後打開 <http://localhost:5317>。直接用 `file://` 打開 `index.html` 不行，YouTube 播放器和背景解析需要 http。

| 檔案 | 內容 |
|---|---|
| `public/index.html`、`app.js`、`app.css` | 介面 |
| `public/lib/actlog.js` | Network log 解析（瀏覽器和 Node 共用） |
| `public/parser-worker.js` | 在背景執行緒解析 log |
| `public/lib/xivapi.js` | 技能分類與圖示 |
| `public/lib/positional.js` | 身位判定 |
| `public/lib/handles.js` | 記住選過的資料夾 |
| `public/clockcal.js`、`clockocr.js` | 讀取畫面時鐘自動校正 |
| `tools/parse-test.js` | 用 Node 測試解析：`node tools/parse-test.js <log>` |
| `tools/serve.js` | 本機預覽用的靜態伺服器 |

推到 GitHub 的 `main` 分支後，`.github/workflows/pages.yml` 會把 `public/` 發佈到 GitHub Pages（第一次要到 repo 的 Settings → Pages，把 Source 設成「GitHub Actions」）。

## 已知限制

- 「目標」列是推測的，轉場、多王同時出現時可能不準
- 一份 log 目前只能對一部影片；一晚分成多次直播時，要分別載入
- YouTube 跳轉有時會停在附近的關鍵影格，誤差約 0.5 秒
- 不支援手機（log 太大，也不能分享畫面）

## 之後可以加的功能

- 匯入預定軸 CSV，標出放早、放晚或漏放的技能
- 一份 log 對多部影片
- 進度統計（每個階段滅幾次、主要死因）
- 匯出／匯入筆記（換電腦用）
